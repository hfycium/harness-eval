## 结构

对话 Agent + `harness-eval-launch` → 批量计划与调度脚本 → 现有 `run-eval.mjs` → 产品适配器 → 独立验收和归档。Runner 每次启动一个 case 和一个产品；批量脚本串行调用 Runner，并保留每项独立运行记录。

Skill 收集目标、产品、配置、超时、评分方式；仅在必要信息无法由项目与上下文确定时询问。对支持请求模型的产品记录对应配置和有效值的可见性；不支持或未验证的产品不擅自声称可切换。凭据由现有机制提供，不写入计划或日志。

批量计划将每个 case × 产品 × 配置视为独立运行，包含独立 run ID、状态、超时、配置摘要、证据与评分目录。首先实现串行，支持单项失败后按明确策略继续或停止；不自动重发不明状态的任务。并行作为后续能力，需限制并发、隔离工作区和结果目录，禁止多个交互终端、共享浏览器 profile 或共享队列产生不受控冲突；暂未验证前不提供并行已可用的承诺。

初版计划文件显式列出 `jobs`，每项给出 case、harness、config 和 timeout；可选 `text_exact` 独立验收。批次目录保存 `batch.json`、`summary.json`、`summary.md` 与验收子目录，单次原始 run 保持独立。进程异常退出但未确认产品状态时必须人工核对，禁止从已生成的摘要推定远端未执行；断点续跑尚未实现。SpreadsheetBench 评分参数暂未接入批量脚本，保留单次 Runner 功能。

GUI、Connector 与 CLI 不同：WorkBuddy/豆包需核对各自 Connector 队列并提供真实 run ID；元宝需要可见交互终端和模式/附件确认。若执行环境不能提供交互，输出具体命令和操作，保留待处理状态，不伪称启动或完成。
