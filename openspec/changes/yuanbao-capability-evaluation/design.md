# 设计

## 决策流程

1. 执行前登记产品入口、可见版本、账号权限、模式、新会话、浏览器与适配器版本、超时、人工参与、输入与评分规则版本，冻结条件；登录及操作由操作员完成并记录。事实不可见即记 `unknown`。
2. 只读盘点可见工具；若工具只有触发后才显示，可提交一次独立、无敏感内容的非基准探针，预先冻结提示、输入及预期观察。提交一次后状态不明则停止，不自动重复；探针与正式评测分开归档。无可核验调用和初始返回时执行能力记 `unknown`。
3. 文件路线分两级：先复核已有 TXT 烟测，记录一次严格通过和其他尝试末尾换行缺失的事实及差异；新一轮预先冻结字节比较和可选规范化规则，分别报告。再以现有 SpreadsheetBench 59196 为共同任务候选，单独确认 XLSX 上传、回收、文件解析、重算来源和固定评分器；适配器仍限 TXT 或产物无法解析时记阻塞，不推定能评分。
4. 代码路线：可先用无害非基准探针观察工具；仅在可见真实调用和初始返回后，设计独立合成题，冻结输入和期望输出并记录运行环境。生成代码或模型自述不证明执行。
5. Bash 路线：可先用无害非基准探针观察工具；仅在当前会话可核验工具调用和初始返回时，单独设计与原 E8 意图相近的云端适配题，冻结 fixture、提示词和判分；记录环境和不可见项。不得将其称为 Windows E8 或直接等同比较。
6. Windows E8：只有证据证明元宝原生命令工具可在本次 Runner 独立 workspace 运行指定命令，且接入支持 JSON 产物，才按原 case 启动一次。

E8 准入采用绑定生命周期：先创建本次隔离 workspace 和唯一运行标识，在同一元宝会话、同一工具及同一工作区内以独立无害文件完成探针，记录工作区身份及可审计的工具返回；探针不得触碰 E8 fixture。随后仅在绑定仍有效时向同一会话移交 E8。切换会话、工具、工作区或工作区映射时证据失效，重新准入；不得把 `prepare` 和 `run` 各自创建的不同 workspace 当成同一个。现有 Runner 若无法维持此绑定则保持阻塞。正式 E8 的初始工具返回必须单独留证；不可见时相应结果为 `unknown`，探针结果不能替代。

## 证据与结果

每次记录产品和模式的可见信息、Runner run ID 或人工探针独立记录 ID、时间、输入与可用产物哈希、提交证据、人工操作、工具原始请求/初始返回及来源、独立验收、评分器状态。缺失的每项写 `unknown` 及原因；产物可独立验收通过而内部工具调用仍为 `unknown`。模型叙述和网页截图只能支持其可见内容。认证信息留在仓库外，不归档凭据。保留失败、超时、阻塞和无法判定的尝试；不从一次成功推断稳定性。

登录失败、权限未确认、附件上传状态不明或会话模式无法确认时停止提交；提交后状态不明、超时或断连时停止自动操作，不重发、不回收可能仍在写入的产物，记录远端可能继续运行。卡片不唯一、下载失败或产物不可解析时保存已有证据并标记对应阶段阻塞；人工处理另记来源与时间。

## 比较范围

先根据项目条件表登记五款产品的入口、模式、模型可见性、人工参与、输入和验收版本。共同任务使用同一冻结任务和验收条件，逐项报告不匹配或未知条件；元宝专属云端适配题只用于描述该入口，单独编号和报告。各产品不可观察的行为不补零，不将总分差异解释为 Harness 的因果效果。

## 命令类准入保护的实现边界

现有适配器仅按 `.cmd` 路径或 E8 标识拦截已知用例，不能证明覆盖全部命令类任务。后续实现须设计明确的任务能力声明和适配器能力契约：元宝路线仅允许显式声明且获准的能力，声明缺失或未知时默认拒绝，不能先假定未声明任务是文件任务。历史冻结 case 可采用有版本和来源记录的受控映射，或按项目规则升版并保留旧版，不得静默改写；文件后缀和题名不能作为唯一判据。

## XLSX 评分隔离

只向产品提供冻结的 prompt 和 inputs；答案、检查器和评分器留在评测侧。若需重算，以产物副本进行，记录原产物哈希、重算副本哈希、重算工具版本和方式；每次独立验收，不覆盖原产物或补写历史原始证据。仅有缓存值时如实说明，不能声称独立重算。

## 网页弹窗与模式记录

适配器只自动处理页面中可见的 dialog/modal/popup 容器：优先依据关闭按钮的无障碍标签、title 或 close/dismiss 类名识别；没有语义标记时，只允许点击容器右上区域显示为 X/× 的按钮。每个检查阶段最多关闭 3 个弹窗，不使用固定坐标，也不点击容器之外的控件。弹窗未识别或关闭后仍阻挡页面时记录 `visible_unresolved` 并交由操作员处理；不得因自动点击失败而重复提交任务。检查点包括页面加载、附件操作前后、提示词提交后和产物导出前。

运行配置明确记录期望界面标签 `Hy4` 与 `专家模式`。登录并新建空对话后，适配器点击“切换模型”，进入“选择模型”列表并选择 `Hy4 新升级 兼顾日常与复杂任务`，再选择专家模式项。发送前读取两个选项的 `aria-checked`，必须均为 `true`；已经选中则不重复点击，菜单项缺失、不唯一或状态无法确认时停止。事件证据记录 UI 选中状态，不据此断言服务端实际模型；`effective_model` 保持 `unknown`，除非产品提供可独立核验的实际模型证据。适配器将各阶段弹窗数量、关闭数量和 UI 菜单选择状态写入独立事件证据文件。

提示词提交前保存可见消息文本基线。提交后以基线差异排除历史文本，并排除与本轮提示词完全相同的回显，再记录新出现的可见文本块及来源选择器。字段命名为 UI 可见候选，不标记为原生助手 Trace；如果没有新文本，写明未观察到。页面稳定本身不能作为回复或任务完成证据。

## 对接

沿用 `yuanbao-playwright-adapter` 的文件任务探索和 `tracetrial-e8-verification` 的独立验收原则。当前 TXT 适配器不提供命令工具，不能把附件上传视为 workspace 挂载。新增能力或适配题在证据充分后另行实现并冻结版本；原 case、fixture 与历史 run 不回写。
