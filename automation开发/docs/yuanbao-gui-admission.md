# 元宝专家模式 GUI 接入准入记录

状态：`unknown / not admitted`。本记录是接入设计判断，不是产品自动化实测。

## 已有证据

- 五款手动验收记录：元宝产物公式静态检查与标准公式一致，但缓存为空、工作簿要求打开时重算；尚无重算确认。此记录证明有一次手动文件任务产物，不证明 GUI 自动化接口存在。[五款手动结果验收](../../docs/2026-11-21-五款手动结果验收.md)
- 项目手动验证计划曾要求使用“元宝专家模式”入口，不切换普通问答或开发者平台调试；当时该入口尚未完成打开与版本确认。计划原件不在本交付副本中。
- 官方元宝开放平台介绍面向已有 Skill 的合作方，提供 Skill 上传、Connector 授权、调试与测试；这不是普通用户专家模式的桌面控制文档。[元宝开放平台](https://open.yuanbao.tencent.com/docs/overview)
- 现有通用适配器只定义 CLI 子进程的 `preflight`、`buildInvocation` 和进程观测；Runner 使用 `spawn` 并从进程退出状态判断生命周期。[适配器契约](../adapters/base.mjs) [Runner](../runner/main.mjs)

## 事实、推断与未知

**事实**：本项目有一次元宝专家模式的手动工作簿尝试及其输出文件；当前项目没有元宝自动化适配器。官方开放平台文档描述的是 Skill/Connector 合作方接入。

**推断**：如果目标入口只能从网页或桌面客户端操作，现有 CLI 子进程适配器不足以表达其会话、文件上传、完成检测和下载步骤。GUI 自动化是一个待验证的实现候选，不是当前已确认的接入方式。

**未知**：实际入口究竟是网页、桌面端还是混合流程；版本与登录状态；是否允许 Playwright、浏览器调试协议或 Windows UI Automation；本地文件上传、任务完成信号、xlsx 下载路径；登录会话是否可在隔离运行环境中稳定复用；模型/模式选择和可见日志范围。

## 准入检查

在编写或运行 GUI adapter 前，需由产品入口摸底确认：

1. 固定产品入口、版本、账号权限及当前是否为“专家模式”。
2. 确认对应网页/桌面自动化技术可稳定定位输入框、附件控件和提交/完成状态；记录权限弹窗与失败状态。
3. 用独立临时目录验证 xlsx 输入上传、结果下载及哈希归档，不把评测答案放进产品可见位置。
4. 明确会话隔离和登录凭据的本地保存边界；凭据不得写入配置快照、日志或仓库。
5. 对模型、模式、Skill 和内部 Trace 的可控/可见性逐项记 `known`、`unknown` 或 `not_supported`，不能从界面未显示推断为不存在。

未满足这些条件时，保持 `not_admitted`；可由人工操作并留存截图、提示词和输入输出文件作为手动现场，但不能将其记成自动化运行。

## 准入通过后的最小生命周期

建议 GUI adapter 提供：`preflight → connect_or_launch → stage_and_upload → submit → observe_and_wait → download_and_hash → close_or_preserve_session`。Runner 统一记录运行 ID、时间、产品版本来源、输入/输出哈希、界面证据引用、可见状态变化、超时和异常；内部执行轨迹仍单独标为不可见或未知。GUI 的截图只能支持截图中可见的事实，不能证明内部工具调用。

该生命周期是设计建议，尚未实现，也未对元宝客户端验证。
