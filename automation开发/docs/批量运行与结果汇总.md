# 批量运行与结果汇总

当前版本按计划顺序串行调用已有 Runner，每项拥有独立 run ID、运行工作区和验收目录。可选择产品和题目，状态与验收结果统一汇总；并行、自动断点续跑和批量 SpreadsheetBench 评分尚未实现。

## 准备计划

复制 `automation开发/configs/batch-text-smoke.example.json` 到仓库内自己的 JSON 文件，按需编辑 `jobs`。每项是一次明确运行，包含 `case`、`harness`、`config`、`timeout`，可选 `verification`；需要重复或多个产品时各写一项，不会自动生成交叉组合。模型通过各产品配置指定；模型是否实际生效仍以产品证据为准。禁止将凭据写入计划或配置。

`verification.type` 支持 `text_exact` 和 `tracetrial_e8_cmd`。`text_exact` 的 `artifact` 是 case 声明的产物路径，`expected` 是评测侧参考文件，可选 `python` 指向本机 Python 解释器。E8 适配题只需指定 `type`，详见 [E8 验收使用说明](TraceTrial-E8验收使用.md)；批次自动调用此验收器尚未通过新的产品批次端到端验证。不填 `verification` 时只归档，不代表已验收。SpreadsheetBench 使用已有单次 Runner 评分参数，暂不支持批量评分。

`on_failure` 可设 `stop`（默认，失败后停止）或 `continue`（普通失败后继续）。超时、人工处理中断、进程中断或无运行记录等状态不明时，一律停止并记录 `needs_reconciliation`；不会自动重试。每次重新启动 batch 都是新的批次，不是断点续跑。

全部任务执行结束但存在验收 `unknown` 时，批次显示 `completed_needs_review`、进程退出码为 2；存在明确失败时显示 `completed_with_failures`。待复核不表示产品失败。

## 启动与查看

```powershell
Set-Location 'F:\大学\大三上\Harness评测-交付'
node .\automation开发\run-eval.mjs batch run --plan automation开发/configs/batch-text-smoke.example.json
```

脚本打印批次目录和每项序号，完成一项再启动下一项。WorkBuddy、豆包工作、元宝网页可能需要人工领取、登录或确认，保持终端开放并按产品提示操作。Connector 两个产品目前共用环境变量名，运行前须确保当前队列根和目标客户端 Connector 一致；如果计划跨产品串行而两个客户端绑定不同队列，不能仅凭一个进程环境自动切换，应拆成不同批次并逐批设置。元宝需要可交互终端和独占浏览器 profile。

另开终端查看当前批次，或运行结束后重新生成汇总：

```powershell
node .\automation开发\run-eval.mjs batch summary --batch 'runs/批次/<批次ID>'
```

目录中 `batch.json` 是调度状态，`summary.json`/`summary.md` 汇总执行、提交、产物、验收及评分；`verification-NNN/` 是独立验收结果。单次原始记录位于 `runs/自动化/<run_id>/`。运行中 `latest_event` 仅反映 Runner 或队列最后可读事件，不是产品内部完整轨迹；元宝人工确认及候选完成信号以其 run 证据为准。

Ctrl+C 会请求停止批次，并尽量标记需核对；进程被强制杀死、系统中断或保存中崩溃时状态可能仍显示 running，需先核对产品进程、队列和单次 run，不能自动重发。各产品记录的工具轨迹范围不同，结果列可并列展示，但过程证据缺失不能补零或当作未发生。
