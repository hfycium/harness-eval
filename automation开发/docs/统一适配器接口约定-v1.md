# 统一适配器接口约定 v1

日期：2026-11-23
状态：文档冻结；产品覆盖与代码一致性见[五产品准入矩阵](五产品接入准入矩阵.md)。

## 分层职责

- **产品适配器**负责产品特有的启动/连接、参数映射、任务提交、可观察信号和产物定位；不得评分，不得伪造产品日志或完成状态。CLI adapter 可用 `preflight`、`buildInvocation`；会话型产品需显式 `runSession`。
- **产品连接器**是产品侧可调用的服务，例如 WorkBuddy stdio MCP Connector，提供领取/提交协议。它不是 Runner adapter，也不等于 MCP 服务协议本身，更不能据此推定其他产品支持相同桌面连接器传输。
- **统一 Runner**建立 run 目录，隔离输入副本，生成配置快照，执行/等待，统一记录状态、超时、事件和错误，并将允许的产物复制归档。队列发布不等于启动产品；人工触发要声明来源。
- **验收器**只验证归档合同、哈希、必需产物和声明的单题预期；**评分器**在评测侧读取归档文件并调用固定版本比较器。二者不启动产品、不修改原件、不把缓存命中解释成真实重算，也不把单题分数解释为基准排名。

## 输入与发布

规范任务至少含 `run_id`、`case_id`、`product_id`、`input`（仓库相对路径及 SHA-256）、`prompt`、`timeout_seconds`、`output_policy`、`trigger_source`、`requested_config`、`evidence_refs`。Runner 在运行目录保存 `case.json`、有效 prompt 与输入副本；验证摘要相符后才能发布。任务发布/队列写入要记录结果和任务摘要。产品不得获得评分 oracle，除非 case 明确要求且风险已隔离。

产品启动分为 `cli`、`api`、`local_mcp_connector`、`gui_manual`、`gui_automated` 等明确入口。适配器声明实际机制；不得将人工点击记录为自动启动。

## 生命周期与结果

统一生命周期：`prepared → submitted → running|awaiting_operator → completed|failed|blocked|timed_out|cancelled`。所有状态含 UTC 时间、来源与证据引用；`unknown` 用于无法观察的子状态。超时由 Runner 统一计时，不自动重发有副作用任务；保留现场并返回 `timed_out`，产品仍可能运行时不得冒险回收其工作区。

结果最少包含：`status`、`reason_code`、`message`、`started_at`、`ended_at`、`timeout_seconds`、`trigger_source`、`artifacts[]`（相对路径、大小、SHA-256）、`evidence_refs[]`。错误分类：`configuration`、`authentication`、`launch_denied`、`transport`、`product_error`、`artifact_missing`、`artifact_invalid`、`timeout`、`verification_blocked`、`internal_error`。外部环境、权限、不可读文件、依赖缺失和证据不足用 `blocked`；有可读产物且内容不符才用 `failed`。返回错误要保留阶段、可重试性（明确值或 unknown）及原始诊断引用，不记录密钥。

## 过程证据、路径与配置

Runner 记录自身事件和原始日志引用；适配器只采集产品实际提供的 stdout/stderr、API 响应摘要、Connector JSONL、可见 GUI 截图/状态。声明 `visibility`（`direct`、`operator_attested`、`inferred`、`unavailable`）；产品自述不能升级成独立观测。产品内部 Trace 不可见时明确 `unknown`。

每次 run 冻结非敏感配置快照：适配器版本/文件摘要、入口、请求模型/模式/推理强度/Skill、超时、沙箱、工具连接器、产品版本及各值的 `source` 和 `status`（`observed`、`requested`、`operator_attested`、`unknown`）。凭据及令牌绝不进入快照。所有路径限于本次新建 run 工作区和显式允许的只读输入；拒绝路径穿越、覆盖已有 run、原件或验收材料。归档前检查符号链接/最终路径并记录哈希。

## 代码对照与最小差异

现有 `adapters/base.mjs`、`codex.mjs`、`dsh.mjs`、`workbuddy.mjs` 与 `runner/main.mjs` 已提供 CLI preflight/invocation、runSession 分支、超时与归档的基础；`contracts/trace-v0.2.schema.json`、`score-v0.2.proposed.schema.json` 提供运行/评分字段草案。WorkBuddy 队列 Connector 位于 `connectors/workbuddy-eval/`，职责独立。

本冻结文件不改变代码。后续对照需优先核实 schema 是否完整表达 `awaiting_operator`、`unknown`、配置来源/证据引用、错误分类、产物安全路径及人工确认；若不兼容，先按仓库 OpenSpec 流程提交变更说明，再做最小字段/校验修改。当前文档冻结不代表五款产品均已实现或准入。
