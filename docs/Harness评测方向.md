# Harness 评测方向

记录日期：2026-11-25。本文记录讨论中提出的评测方向与采用建议，供后续选题使用；具体题目、指标与评分规则仍需试跑后确定。

## 完整评测维度

以下是待细化的评价方向，不代表已经具备评分器或获得实测结果。

| 维度 | 核心问题 | 可观察指标或实验 |
|---|---|---|
| 任务完成 | 结果是否正确、完整 | 任务成功率、产物质量、独立答案检查 |
| 任务规划 | 能否处理依赖关系并调整执行 | 多步骤任务的依赖处理、调整、重复或无意义循环；可见计划作为补充 |
| 工具使用 | 能否选择和组合合适的工具 | 工具选择、参数、调用结果，以及浏览器、文件和命令等协作 |
| 上下文与状态 | 能否在多步骤和多轮中保持一致 | 长任务中变更要求、多轮继续、修改文件后的状态一致性 |
| 异常处理与恢复 | 能否发现错误并继续 | 工具故障、超时、缺失文件、异常返回后的响应、恢复和无效重试 |
| 可观测性 | 用户能看到什么 | 状态、工具调用、错误、日志和证据；区分可见信息与内部轨迹 |
| 可干预性 | 人能否改变执行过程 | 暂停、终止、修改目标、审批、纠正和恢复执行 |
| 安全与权限 | 是否遵守操作边界 | 越权、未经授权的文件修改、敏感信息保护、危险操作确认和提示词注入 |

横向记录效率与成本（耗时、token、调用和重试次数、人工介入成本）及稳定性（重复运行结果的波动）。能观察多少记录多少，缺失时标记未知；无需提前给维度加权。

## 当前优先评测

| 方向 | 关注什么 | 获取证据的方式 |
|---|---|---|
| 任务完成 | 任务是否完成，产物是否正确、完整 | 使用公开任务和独立评分器检查最终结果 |
| 工具使用与任务推进 | 能否使用工具并完成有依赖的多个步骤 | 检查产物及可见工具调用；不以是否展示计划作为唯一标准 |
| 异常恢复 | 工具出错或任务受扰动时如何响应 | 同一任务设置正常与故障条件，记录故障是否实际触发、响应及最终状态 |
| 可观测与干预 | 能看到什么，能否停止、纠正或调整正在执行的任务 | 查看实际可见日志与状态；通过操作验证干预效果 |

## 五类实验

| 实验类型 | 主要关注 | 示例 |
|---|---|---|
| 基础任务 | 完成质量、工具使用 | 同一份文件处理任务及独立验收 |
| 复杂长任务 | 规划、状态保持 | 有先后依赖的多步骤工作，中途更新要求 |
| 多工具协作 | 工具选择和信息交接 | 检索、读取文件、执行操作并整合结果 |
| 故障注入 | 异常发现、恢复和稳定性 | 正常条件与真实可控故障条件对照 |
| 人工干预 | 观察、控制及权限 | 执行中停止、纠正目标或审批操作 |

可以复用同一任务，分别做正常、故障和人工干预三个条件；需保证各条件的输入、触发方式和验收规则明确。

例如故障可以是读取失败、网络中断、超时或返回格式异常；状态变化可以是新增要求、更新文件后继续；人工干预可以是要求停止、纠正方向或审批危险操作。这些是候选场景，尚未全部实现或验证。

## 两层结论

- **产品整体表现**：从用户视角记录结果质量、耗时、稳定性与人工介入等，注明产品、模型及实际接入条件。
- **Harness 相关行为**：结合可见工具返回、状态变化和外部故障，描述观察到的执行与恢复行为。可见行为可能由模型、提示、工具和环境共同产生；不可见的执行循环、检查点或内部机制不写成已验证事实。

能力状态区分：**确认支持、确认不支持、实验中未观察到、当前条件下无法验证**。判断“确认不支持”需要足够证据，仅有一次未观察到不够。

## 结果报告与实施阶段

报告分别呈现任务结果、执行过程、规划与工具等行为、可观测性、可干预性、安全权限、效率成本、局限与归因。每项实验保留最终产物、实际可见过程、原始证据以及结论与证据充分程度；产品支持、确认不支持、未观察到和无法验证应分别记录。

1. **准备**：明确维度、选题、评分和证据要求，优先复用公开任务。
2. **预实验**：少量试跑，检查题目是否能执行、评分和区分行为，修订规则。
3. **正式评测**：冻结任务、预算、配置和评分，记录所有分配、失败、缺失与重跑；重复次数依据资源确定，三次只能反映初步波动。

通用任务用于跨产品比较；编码、办公、浏览器等可根据产品入口设置专项任务，按实际参加的产品与条件报告。

## 设计与结论原则

- 正常、故障和人工干预可以复用同一任务背景，但分别记录条件及结果。故障实验需要可核验的实际故障，不能只让产品假设故障。
- 分别记录任务结果、可见过程、原始证据和证据缺口。结果正确不代表执行过程已验证；看不到的部分标记未知。
- 产品整体表现与可观察的 Harness 行为分别描述；模型、Skill、工具和环境的影响未排除时，不把结果直接归因于某个组件。
- 使用公开测试集建立基础结果，再针对故障恢复、状态保持等缺口设计少量专项题。任务、评分器和改编版本须留档。
- 暂不为各维度分配权重或综合排名。重复运行用于观察初步波动，三次不足以支持稳健的稳定性结论。
