## 主要发现

1. **结果信号冲突被正确写入报告。** 四份产物都记录了成功样式的输出与非零退出状态并存。支持的结论仅限于本次可见结果与报告相符。
2. **退出码随执行路径不同。** Codex、DSH 记录 `1`，WorkBuddy、豆包工作记录 `23`。现有材料不能确定差异来自产品 Harness、命令包装层还是运行环境，不能直接将其解释为产品优劣。
3. **观测能力影响验收强度。** CLI 归档、Connector 事件和客户端工具回执覆盖范围不同；一条工具调用记录能核对该次返回，但不能单独证明完整会话中没有额外调用。
4. **元宝目前是接入阻塞，不是任务失败。** 公开代码运行能力没有证明其运行环境能访问本次独立 workspace 或运行 `cmd.exe`；现有网页适配器也不满足 E8 JSON 产物合同。
5. **模型归因仍不充分。** 实际生效模型、推理强度和完整轨迹并非每次都可验证，因此当前差异只能描述为具体产品与接入条件下的端到端观察。

## ChatAnywhere 模型接入 smoke（2026-11-26）

用户轮换 Key 后，Codex 和 DSH 依次运行命令探针。两次均以请求配置 `deepseek-v4.1-flash-1017` / `high` 启动，Trace 记录 Windows DPAPI 凭据来源；进程退出码均为 0，Runner 回收的 `outputs/probe.txt` 与输入文件 SHA-256 相同（`976a7d98…3f4ea6`）。这验证了新 Key 下两条 CLI 请求和文件回收链路各一次。

这不是 Harness 评测结果：两个 Trace 的实际模型、推理强度仍未知，产品版本也未知；没有 Oracle，`benchmark_status=blocked`，`task_success_verified=false`，无评分。运行证据：[Codex run](../runs/自动化/2026-11-26T144547-444Z-codex-command-probe-codex-70f59423/trace.json) · [DSH run](../runs/自动化/2026-11-26T144748-509Z-codex-command-probe-dsh-140c86dd/trace.json) · [接入变更记录](../openspec/changes/chatanywhere-model-provider/tasks.md)。

下一题建议：有条件地准入 `ds-format-excel-sheets`，其官方 evaluator 定义了四个检查点；代码检查发现 checkpoint 3 对缺少指定填色的单元格只写 warning、不返回失败，需用独立严格检查器补足。OwnCloud 输入尚未取得、官方 commit 尚未冻结，因此目前只是候选，不能开始正式运行。较难的 `ds-predictive-modeling` 暂列后续候选。详情见[公开测试集候选](公开测试集候选.md)。

难度梯度中的任务并非都只有通过/失败：SQL 加权为 0–6 分，格式题四个检查点合计 0–4 分，预测题按指标阈值给 0/2/3 分。当前 Runner 可以按声明路径归档文件并记录 SHA-256，但 TheAgentCompany 专用评分器只实现了 SQL；格式题和预测题仍需各自评分器。WorkBuddy、豆包工作对 XLSX 的实际往返能力也未验证。因此下一道正式产品任务前先完成输入冻结、四款文件准入、Trace 证据检查和 scorer 样例校验。具体检查见[公开测试集候选](公开测试集候选.md)。
