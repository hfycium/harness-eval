## WorkBuddy：证据层次

1. **评测侧独立观察：** Runner 归档工作簿的公式仍在；`data_only` 缓存读取为 D、A、D；官方固定 revision `e2758ac01c6c52ef746bf0d53b2fd01dbc42dd2` 对声明目标单元格的比较通过。记录还包含归档哈希和 run/trace/case 一致性检查。
2. **Excel 重算操作：** `workbuddy-59196-runner-score-01` 记载操作员确认对副本执行 `Ctrl+Alt+Shift+F9` 并保存；但复核副本与原归档 SHA 相同，缓存本来已是 D、A、D。保存文件字节不变无法独立证明 Excel 实际执行重算；因此此项是操作员确认，不是评测侧独立观察。
3. **其他 WorkBuddy 单题记录：** 自动评分 run (`...072508...`) 通过，但明确使用产品保存缓存值、没有独立 Excel 重算。它与用户确认的副本重算是不同证据链，不应合并表述为“Runner 观察到 Excel 重算”。官方单题通过证明所比较缓存值/公式满足该单题，不证明重算过程或基准得分。

复核过程中不改 WorkBuddy 原始产物；原始和已有失败/初次记录均保留。引用目录中的 `verification-v5/score.json` 等是独立复核输出。

## 元宝：阻塞与人工步骤

现有评分尝试无法由 openpyxl 打开工作簿，错误发生在 custom XML 解析阶段，不能据此称为 H3:H5 错误。当前已有证据仅支持静态公式核对及“工作簿需打开重算”的手动验收记录；缓存读值、桌面 Excel 重算和保存后的独立读取尚未完成。COM 在此非交互会话失败后，没有尝试修改原件或绕过解析器重写工作簿。

下一步需人工在 Excel 桌面端对**评测侧副本**打开并触发完整重算、保存；记录操作员、时间、步骤及副本前后 SHA-256。随后评测侧独立只读打开副本，检查目标单元格公式和计算值，运行固定版官方单题比较器，将 JSON、哈希及操作员确认一并保存到新的复核目录。若 Excel 也无法打开，应记录 Excel 错误和版本，继续保持 `blocked`；不要把 XML 错误归类为答案不匹配。原件不改。

## Codex：依赖结论边界

历史诊断记载隔离自动化沙箱账户下裸 `codex` 先解析到执行策略禁止的 `codex.ps1`，而 `codex.cmd login status` 显示该隔离账户未登录。后续 MXC 环境处理显式在 Windows Codex 调用指定 `windows.sandbox=mxc`，保留 `--sandbox workspace-write`；命令读写探针和 SpreadsheetBench 单题任务均完成。故原先命令被拒绝/环境依赖阻塞在该适配器配置范围内已解决，不能推断隔离账户登录态已解决，也不能推广到其他 Windows 用户。

仍未知：目标用户与自动化运行身份是否一致、其他用户的 MXC 策略/CLI 登录配置、模型元数据 fallback 下实际模型与推理强度、不同运行条件稳定性。无需再以同一条件启动正式评测；若迁移用户环境，先在目标用户同一终端核对 `codex.cmd login status` 和版本，再做无副作用探针。
