# 公开测试集候选

记录日期：2026-11-25。用于筛选 Codex、DSH、WorkBuddy、豆包工作的后续任务；元宝接入边界另行核实。本记录是候选调研，尚未运行或验证具体题目的四产品兼容性。

| 测试集 | 任务与评分 | 对本项目的价值 | 接入条件与待核实事项 |
|---|---|---|---|
| [TheAgentCompany](https://github.com/TheAgentCompany/TheAgentCompany) | 模拟企业中的文件、数据、代码及多工具任务，按题目检查点评分。[官方评分说明](https://github.com/TheAgentCompany/TheAgentCompany/blob/main/docs/EVALUATION.md) | 优先筛选文件处理类题目，观察工作区操作和多步骤任务完成情况。 | 官方任务以 Docker 镜像及模拟服务为基础；部分评分需要轨迹或 LLM。需逐题核实题目与输入获取、评分规则、四产品访问环境及许可。 |
| [Terminal-Bench](https://github.com/harbor-framework/terminal-bench) | 终端环境下的实际任务，任务附验证程序；通过 Harbor 运行。[论文](https://arxiv.org/abs/2601.11868) | 适合观察工具执行、环境操作和问题解决。 | 需确认具体版本与题目、Docker 环境，以及四款产品进入同一环境的方法；修改环境或任务后应标明改编。 |
| [Tool-Bench](https://github.com/OpenRouterTeam/tool-bench) | 使用 MCP 工具操作模拟服务；离线验证请求、状态和变更，明确区分失败、环境错误与无法判定。[评分与运行说明](https://github.com/OpenRouterTeam/tool-bench#running-it) | 适合观察工具选择、调用顺序和最终状态。 | 官方流程依赖 Harbor、Docker 等组件，需确认四款产品能否接入题目所需 MCP 服务，并评估适配成本。 |
| [AgentDojo](https://github.com/ethz-spylab/agentdojo) | 使用模拟工具和任务评估间接提示词注入；分别关注正常任务完成与攻击是否成功。[论文](https://arxiv.org/abs/2406.13352) | 安全、权限边界及工具使用专项候选。 | 需要把产品接入其模拟工具和攻击环境；具体题目、评分器运行及四产品适配均待核实。 |
| [τ²-bench](https://github.com/sierra-research/tau2-bench) | 模拟客户交互及服务工具，按任务规定检查数据库状态和沟通等结果。[评分说明](https://github.com/sierra-research/tau2-bench/blob/main/docs/evaluation.md) | 多轮交互、任务推进及工具使用候选。 | 涉及模拟用户和工具；不同题目的评分组成不同，部分沟通检查可能使用模型。四产品接入待核实。 |
| [STATE-Bench](https://github.com/microsoft/STATE-Bench) | 面向有状态企业任务的 Agent 与记忆评测，提供主赛道及学习赛道。[运行说明](https://github.com/microsoft/STATE-Bench/blob/main/docs/RUN_BENCHMARK.md) | 状态保持、长任务和重复运行候选。 | 需逐题核实数据、评分规则、记忆协议及四产品接入；不能把答案正确直接等同于某个记忆机制有效。 |
| [LongMemEval](https://github.com/xiaowu0162/LongMemEval) | 公开长对话记忆题目和评测流程。 | 跨轮信息保持候选。 | 主要测长对话记忆，不直接证明任务中断恢复；评测器及多轮输入方式需逐题核实。 |
| [AgentRetry](https://github.com/MHKhan50/agentretry-tool-recovery-benchmark) | 合成故障场景覆盖执行前失败、提交后超时和陈旧观察，记录完成和重复副作用等。 | 故障恢复与防重的探索候选。 | 作者说明每轮只有一个关键操作，属于简化环境；实际题目、评分器和四产品接入尚未验证。 |

## 建议顺序

1. 从 TheAgentCompany 筛选 2～3 道文件类候选，优先检查客观评分、输入和运行环境。
2. 核实每题四款产品的接入方式与评分器可用性，选择一道进行试跑。
3. Terminal-Bench 和 Tool-Bench 留作命令操作、工具调用专项候选。

AgentDojo、τ²-bench、STATE-Bench、LongMemEval 和 AgentRetry 是按维度补充的候选，暂未核实到适合四款产品直接运行的具体题目。可观测性和人工干预暂按产品界面及运行证据单独检查，尚未确认能直接复用的公开评分集。

## 影响力较高的补充候选

这里参考公开论文、官方榜单与仓库维护情况，不把热度当作质量或四产品适配性的证明。暂未验证具体题目及本项目接入。

| 基准 | 使用价值与评分 | 本项目限制 |
|---|---|---|
| [SWE-bench Verified](https://github.com/SWE-bench/SWE-bench) | 真实软件仓库问题，使用测试程序验收补丁；编码 Agent 的对照候选。 | 编码专项，不宜用作全部办公产品的唯一共同题；官方评测依赖 Docker，资源需求较高，需固定版本和隔离评测。 |
| [OSWorld](https://github.com/xlang-ai/OSWorld) | 多应用桌面操作，公开任务、虚拟环境与评测程序，可观察 GUI 执行。 | 需 Agent 控制基准虚拟桌面；四款产品的接入和 Windows 本地环境兼容性未知。后续版本的题目访问条件另查。 |
| [GAIA](https://huggingface.co/datasets/gaia-benchmark/GAIA) | 通用助手任务，部分题需检索或附件，答案明确；验证集有答案，测试集答案不公开。 | 数据访问需经过 Hugging Face gating，官方要求不要公开传播题目；答案正确不能单独证明执行机制。 |
| [WorkArena](https://github.com/ServiceNow/WorkArena) | ServiceNow 知识工作任务；WorkArena++ 将基础操作组合成复杂工作流。 | 依赖 ServiceNow 实例与浏览器环境，四产品适配和资源成本待核实。 |

Terminal-Bench 已列入上表，它拥有公开版本和榜单，值得作为终端专项优先候选。正式测试前固定数据集版本、检查评分合同和许可，并用实际任务验证接入；小规模子集只报告子集结果。

## 优先选择的理由与建议

目前找到的是测试集及任务类型，**尚未筛出并核验具体题目 ID**；下列均为选题建议，不是已验证可运行或已完成评测。

| 优先级 | 测试集与建议题型 | 选择原因 | 具体建议与待核实事项 |
|---|---|---|---|
| 1 | TheAgentCompany：文件处理、数据整理 | 场景接近实际办公，有任务检查点和公开评分程序，适合建立四产品的共同任务结果。 | 先筛 2～3 题，核对输入、评分是否客观、Docker 和服务依赖，再选一题试跑；部分题依赖轨迹或 LLM，不能假定全是规则评分。 |
| 2 | Terminal-Bench：文件、命令及环境操作 | 具有公开版本、榜单和独立验证程序，适合观察多步骤工具执行。 | 固定版本选少量任务；先确认四款产品能否在等价的基准环境中操作，若修改任务或环境必须单独标记。 |
| 3 | Tool-Bench：调用 MCP 工具并改变状态 | 可用请求记录与环境最终状态检查工具使用，对观察调用与副作用有帮助。 | 先验证四款产品能否接入其 MCP 和模拟服务，再确认具体题目及其评分合同。 |
| 4 | AgentRetry：提交后超时、重试防重 | 故障发生位置和重复副作用贴近异常恢复问题。 | 作为探索候选，先审查题目和评分器；作者说明每轮只有一个关键操作，结论不推广到复杂工作流。 |
| 后续专项 | AgentDojo：提示词注入；STATE-Bench / LongMemEval：状态或记忆；τ²-bench：多轮工具交互 | 这些基准分别覆盖安全、状态保持及对话交互，适合补充共同任务看不到的现象。 | 逐题核对评分和四产品工具/会话接入；记忆答题成绩不能单独证明内部记忆机制。 |
| 后续专项 | SWE-bench Verified：软件修复 | 真实仓库问题和测试验收适合作为编码能力参照。 | 优先用于编码专项，不以它单独评价办公产品；检查 Docker 资源、版本与题目泄漏风险。 |
| 后续专项 | OSWorld：跨应用桌面任务 | 有虚拟桌面、任务与评测程序，适合研究桌面控制。 | 先确认四产品是否能控制同一个基准环境；新版任务的访问要求另行核实。 |
| 后续专项 | GAIA：检索与附件问答 | 问题有明确答案，覆盖助手工具使用。 | 先核验账号访问和数据许可；遵守不公开传播题目的要求，仅将结果理解为对应任务表现。 |
| 暂缓 | WorkArena：企业浏览器工作流 | 企业场景和组合任务具有参考价值。 | 依赖 ServiceNow 实例及浏览器环境，先评估接入、资源和使用条件。 |

可观测性、人工干预和效率成本还要配合产品界面检查、运行日志和操作记录；上述测试集不保证直接覆盖这些项目。

选题关注的能力和证据要求见[Harness 评测方向](Harness评测方向.md)。
