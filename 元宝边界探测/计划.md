# 元宝边界探测计划

## 目标

核实元宝在当前产品入口和会话中实际能做什么，重点区分：

1. Python/C++ 等代码运行能力；
2. 文件上传、读取、生成和下载能力；
3. 元宝开放平台的 Skill / MCP Connector 服务接入能力；
4. 能否通过元宝原生工具，在 Runner 为本次任务创建的独立 workspace 中执行 Windows 命令。

只有第 4 项得到会话级证据，才考虑启动 E8。公开产品说明、文件上传、模型自述和生成文件都不能单独证明第 4 项。

## 已完成的公开资料调研

检索日期：2026-11-25。以下区分官方直接表述、由官方架构材料支持的判断和非官方线索；公开资料不能替代当前产品会话的实机工具证据。

| 主题 | 已找到的证据 | 对 E8 的含义 |

| 文件处理 | 官方材料说明文件上传、解析和导出；没有承诺任意本机路径访问。 | 附件处理不等于原目录访问。 |
| 非官方线索 | 第三方文章声称元宝有 Bash 工具和 `/data/workspace` 会话沙箱。该材料不是官方证据。 | 仅提示可在实机工具列表中留意云端 Bash；即使属实，也不等于能访问本机目录或运行 Windows `cmd.exe`。 |

### 当前结论

没有公开证据证明元宝原生工具能在指定 Runner workspace 执行 `cmd.exe /d /c <command>`。结论应写为 **公开资料未说明、当前无法确认**，不能写成“元宝产品绝对不支持”。对开放平台 Connector 的 CLI 限制只适用于该 Connector 接入路径，不自动代表所有元宝原生工具能力。

公开资料已能回答一般能力边界；后续实机盘点只在操作员实际看到新的候选原生工具时进行。若没有该工具，不必为验证假设而提交 E8，也不需要用本机脚本模拟元宝调用。

## 阶段一：公开资料调研

- 优先查看腾讯元宝官方网页、帮助中心、开放平台文档和官方应用商店说明。
- 分开记录网页端、Windows 客户端、移动端及专家模式的说明；产品入口或版本未核实时标为 `unknown`。
- 对每条结论记录原文要点、页面标题、URL、发布日期或检索日期，以及它能证明和不能证明的范围。
- 特别核实 Python/C++ 运行环境、文件访问范围、`cmd.exe` 支持情况、Connector 的授权和服务边界。
- 不能从“官方资料未说明”推断为“产品不支持”。

## 阶段二：当前会话工具盘点

由操作员在元宝实际产品会话中查看并记录：

- 产品入口、平台、可见版本和所选模式；
- 会话实际显示的工具名称、说明、授权状态和调用方式；
- 工具调用记录能否区分模型文本与真实工具请求/返回；
- 工具是否暴露工作目录、运行环境和初始进程返回。

截图只记录画面中可见事实。模型说“我运行了”不视为工具证据。不要分享登录凭据、Cookie、个人资料或敏感页面。

## 阶段三：无害边界探针

仅当会话中确实出现可调用的候选原生工具后再进行；不调用 E8 fixture，不启动 E8 Runner 任务。

1. 为探针创建全新的临时工作区，只放无敏感信息的标记文件；标记内容使用随机字符串，避免与模型上下文混淆。
2. 先确认该目录确实是本次探针目标目录，并记录创建者、绝对路径及文件哈希。
3. 通过元宝界面中实际显示的候选工具，尝试读取标记文件，并记录工具名称、实际请求、工具原始初始返回和可见工作目录。
4. 如需确认写入能力，只允许在该临时工作区创建一个新的探针结果文件；不得覆盖已有文件或访问工作区之外路径。
5. Python/C++ 代码运行与本地命令工具分开探测、分开记录。上传文件后能被模型读取只证明附件可读，不能证明运行时能访问原目录。
6. 不重试、不轮询、不委托其他 Harness 或本地脚本执行探针命令。若工具结果不明确，停止并记为 `unknown`。

探针文件和日志放在本目录下独立的探针资料区，凭据和浏览器配置不得放入仓库。若要验证 Runner workspace，必须使用 Runner 实际为该次探针创建的目录；仅测试本目录不能替代该项验证。

## 阶段四：E8 准入判定

下列条件须全部有证据，缺一项即 `not_admitted`，不领取、不提交 E8 任务：

- 元宝当前会话提供可审计的原生命令执行工具；
- 工具能执行 Windows `cmd.exe`；
- 工具的实际工作目录已证明是该次 Runner 独立 workspace；
- E8 输入由 Runner 放入该 workspace，且不需要检查、复制、编辑、替换或包装 fixture；
- 初始工具返回能够直接用于报告，不需要重试或从其他来源推断；
- 当前 Runner/适配器能够支持 E8 要求的 JSON 产物，且不绕过原有准入检查。

准入证据不足时，只报告阻塞和所缺证据；不将其写成评测失败或已完成。

## 阶段五：通过准入后的单次 E8

只有阶段四全部通过后，才按 E8 case 原文执行一次：使用既有 Runner 和适配器，创建新 run；只允许元宝原生工具调用一次指定命令；只依据该次工具初始返回生成规定的 JSON；保留 Runner 原始 run、事件证据、报告哈希、时间、版本/模式和工具返回。之后独立检查 JSON 字段与类型，并分别报告报告内容、原生工具证据、过程轨迹可见性和评分器状态。`oracle: not_integrated / manual-pilot` 不得描述为自动评分已完成。

## 当前状态

- 官方公开资料已核对：产品说明提及 Python/C++ 在线代码运行；开放平台说明支持合作方 Connector；腾讯云文章描述隔离沙箱与沙箱内文件挂载。没有公开证据证明元宝原生工具能访问本次 Runner workspace 或执行 `cmd.exe`。
- 以上结论为 `unknown / not_admitted` 的证据状态，不等于产品明确不支持。
- 当前元宝网页适配器不集成本地命令工具，且只准入单个 TXT 产物；E8 当前要求 JSON 产物，因此该适配器路径目前不能执行 E8。
- 当前元宝会话的工具列表与 workspace 访问能力尚未实机核实。以上为待完成事项，不代表元宝产品绝对不支持。
