# Harness 竞品评测周报（草稿）

日期：2026 年 11 月 28 日  
作者：洪锋烨

## 本周项目进展

- 完成上周首轮产物复核。WorkBuddy 公式与缓存值核验、固定版本官方单题比较通过；Excel 桌面端重算仅有操作员确认，缺少独立证据，仍属部分确认。Codex 在记录的 Windows 用户和配置下排除运行环境阻塞后，完成 Runner 运行、产物归档及官方单题比较。元宝工作簿仍未完成独立重算与评分。详见[首轮产物复核记录](https://github.com/hfycium/harness-eval/blob/main/docs/2026-11-23-首轮产物复核记录.md)。
- 建设并迭代自动化评测工具。Runner 负责准备隔离任务、管理运行记录和产物归档；产品适配器处理 CLI 或桌面队列接入；独立评分器读取归档记录和产物进行验收。桌面产品通过 MCP Connector 队列交接任务，仍需人工或产品侧任务触发来领取；Runner 发布任务本身不会启动桌面应用。
  - 设计亮点：CLI 与桌面端使用不同接入方式，共用 run_id、运行记录、产物归档和独立验收流程。
  - 迭代过程：单产品运行与验收 → Connector 队列交接与产物回收 → 证据索引、串行批次和公开题评分。Connector 日志记录 MCP 调用边界，不代表产品完整内部 Trace；各产品可采集的过程记录不同。
  - 材料：[自动化工具说明](https://github.com/hfycium/harness-eval/blob/main/automation开发/README.md)、[新测试集接入流程](https://github.com/hfycium/harness-eval/blob/main/automation开发/docs/新测试集接入流程.md)。

- 开展 TraceTrial E8 Windows 命令结果观察实验。四份产物都记录了成功样式文本与非零退出码；
    - WorkBuddy 与豆包工作的报告和提取到的工具回执经人工核对一致。
       - WorkBuddy 使用 Bash 调用 CMD 改编夹具，与其他产品的命令入口不同；退出码差异的转换位置仍待定位。
    - Codex 运行日志显示执行前读取过题目夹具，违反用例限制；
    - DSH 尚未逐项完成约束核验，部分运行的完整调用次数也无法确认，因此本轮只报告观察到的现象，不作正式通过判定或基准评分。
    - 元宝尝试执行 E8 未成功：提示词级试跑回复报告退出码 127，且未见两条状态文本；由于执行模式、夹具和 Runner 工作区访问未确认，该结果记录为试跑失败，不计入正式 E8 评分
  - 结果与证据：[Codex/DSH 首轮复核](https://github.com/hfycium/harness-eval/blob/main/runs/复核/2026-11-24-tracetrial-e8-cmd-人工复核.md)；[WorkBuddy/豆包工作工具回执复核](https://github.com/hfycium/harness-eval/blob/main/runs/复核/2026-11-25-E8办公产品工具回执复核.md)。
  - 元宝提示词探索：[记录](https://github.com/hfycium/harness-eval/blob/main/runs/复核/2026-11-28-元宝E8提示词探索记录.md)。

- 开展 TheAgentCompany SQL 任务预实验。准备公开任务的本地输入和 Windows 路径适配，使用本地独立评分器检查三个输出文件。Codex、DSH、WorkBuddy、豆包工作各运行一次，均得 6/6；这是本地评分结果，不是官方 Benchmark 成绩。当前结果说明本题下的任务接入、产物回收和评分链路可用，但单次满分无法体现产品差异或跨次稳定性。本地评分规则尚未与固定版本的官方评分器核验等价。元宝网页接入不支持本题的多文件产物合同，因此未参加。
  - 问题与改进：四款均满分，区分度不足；后续筛选更有区分度且评分客观的任务，并核验本地评分规则与官方实现的等价性。
  - 评分记录：[Codex](https://github.com/hfycium/harness-eval/blob/main/runs/复核/theagentcompany-sql-codex-01/verification.json)、[DSH](https://github.com/hfycium/harness-eval/blob/main/runs/复核/theagentcompany-sql-dsh-01/verification.json)、[WorkBuddy](https://github.com/hfycium/harness-eval/blob/main/runs/复核/theagentcompany-sql-workbuddy-01/verification.json)、[豆包工作](https://github.com/hfycium/harness-eval/blob/main/runs/复核/theagentcompany-sql-doubao-work-01/verification.json)。

- 调研后续公开测试集。整理候选测试集、任务方向和接入条件。下一步优先筛选步骤更多、结果可客观检查，且四款产品能够接入的任务。[公开测试集候选](https://github.com/hfycium/harness-eval/blob/main/docs/公开测试集候选.md)

## 下周计划

1. 探索元宝的评测边界。针对本次 E8 提示词试跑未成功、回复报告退出码 127 的现象，核实文件输入与产物回收、代码或命令运行环境、Runner 工作区访问和工具过程证据，区分产品能力限制、适配器缺口与任务环境不匹配。
2. 从公开测试集筛选更有区分度且评分明确的候选题，先核对输入、评分和四款产品的准入条件。
3. 根据实跑中发现的过程证据缺口，继续完善采集与验收，记录无法验证的项目。
4. 核对 E8 中 WorkBuddy 与其他产品的退出码差异，对照实际命令、夹具和工具回执，确认差异出现在哪个环节。
