# Harness 竞品评测周报（草稿）

日期：2026 年 11 月 28 日  
作者：洪锋烨

## 本周项目进展

- 跟进上周首轮产物复核。WorkBuddy 公式和缓存检查及官方单题比较通过；Excel 重算由操作员确认，未独立证明重算动作。Codex 在记录的 Windows 配置下解决运行阻塞，并完成单题评分。元宝工作簿仍因解析错误无法完成独立重算与评分，继续跟踪。详见[首轮产物复核记录](../../docs/2026-11-23-首轮产物复核记录.md)。
- 建设并迭代自动化评测工具。搭建统一运行入口，通过各产品适配器提交任务，回收产物并保存运行记录，再使用独立评分器验收。Codex、DSH 通过 CLI 启动；WorkBuddy、豆包工作通过 Connector 队列交接，需在客户端手动触发领取。
  - 设计亮点：统一 Runner 同时编排两种不同执行路径——CLI 直接运行，以及桌面端通过 Connector 领取、执行、提交；队列事件、产物哈希和运行记录能按同一 run_id 对齐。证据索引保留日志来源和缺失项，避免把 Connector 记录误当成产品完整 Trace。
  - 迭代过程：单产品运行与验收 → 队列交接与产物回收 → 证据索引、串行批次和公开题评分。不同产品的工具轨迹覆盖仍有差异。
  - 材料：[自动化工具说明](../../automation开发/README.md)、[新测试集接入流程](../../automation开发/docs/新测试集接入流程.md)。

- 开展 TraceTrial E8 命令结果观察实验。使用 Windows 改编题，让产品记录命令输出和退出状态，检查它能否识别二者冲突。Codex、DSH、WorkBuddy、豆包工作的产物均记录了成功样式文本与非零退出码；已对照可见工具返回进行复核。部分运行缺少完整会话证据，调用次数等检查仍为未知；WorkBuddy 使用 Bash 调用 CMD 的改编方式，与其他入口条件有差异。元宝网页适配器尚未接入本地命令工具，也未确认元宝能访问 Runner 工作区执行该命令，因此未参加本题。
  - 问题与改进：工具调用证据不完整，部分过程无法判定；已结合可见工具回执复核，并在验收中将缺失项标为未知，后续继续完善采集。
  - 结果与证据：[五款产品评测总结](../../docs/五款产品评测总结.md)。

- 开展 TheAgentCompany SQL 任务预实验。准备公开任务的本地输入及 Windows 路径改编，使用独立评分器检查三个输出文件。Codex、DSH、WorkBuddy、豆包工作各运行一次，产物本地评分均为 6/6；四款均满分，题目区分度不足，本轮主要验证任务接入和评分链路。评分器尚未与固定版本官方评分器核验等价。元宝网页适配器当前仅支持已审查的单个 TXT 或 XLSX 产物，尚不支持本题三个产物的回收；元宝侧能否处理数据库也未验证，因此未参加本题。
  - 问题与改进：四款均满分，无法拉开差异；后续筛选更有区分度且评分客观的任务，并对照固定版本官方评分器核验本地规则。
  - 评分记录：[Codex](../../runs/复核/theagentcompany-sql-codex-01/verification.json)、[DSH](../../runs/复核/theagentcompany-sql-dsh-01/verification.json)、[WorkBuddy](../../runs/复核/theagentcompany-sql-workbuddy-01/verification.json)、[豆包工作](../../runs/复核/theagentcompany-sql-doubao-work-01/verification.json)。

- 调研后续公开测试集。整理候选测试集、任务方向和接入条件。下一步优先筛选步骤更多、结果可客观检查，且四款产品能够接入的任务。[公开测试集候选](../../docs/公开测试集候选.md)

## 下周计划

1. 探索元宝的评测接入边界。因元宝接入条件尚不满足或未确认而未能运行；下周核实元宝的文件输入与产物回收、代码或命令运行环境，以及现有适配器能够支持的任务，再区分产品能力与适配器缺口，选择可行的同题或适配方式。
2. 从公开测试集筛选更有区分度且评分明确的候选题，先核对输入、评分和四款产品的准入条件。
3. 根据实跑中发现的过程证据缺口，继续完善采集与验收，记录无法验证的项目。
