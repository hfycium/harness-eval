# 报告目录规则

## 文件用途

- `weekly/`：项目周报的归档版，使用 Markdown，记录完整进展、问题和计划。
- `邮件/`：可直接复制到邮件正文的纯文本稿，使用 `.txt`，内容与对应周报基本一致；不保留 Markdown 标题、加粗、列表或链接语法。

## 内容规则

- 保持事实、状态和范围与验收记录一致，不夸大静态检查、预实验或未完成事项。
- 邮件稿只调整称呼、排版和链接呈现；不擅自删改周报的实质内容。
- 纯文本邮件稿中的链接写成完整 URL，确保复制到邮件后可直接打开。
- 署名和日期以对应周报内容为准；不要在邮件稿或规范中写入本机磁盘路径。

## 引用规则

- 报告引用的材料必须位于本交付仓库，并已提交到 GitHub `main` 分支。
- GitHub 链接统一使用 `https://github.com/hfycium/harness-eval/blob/main/<仓库内相对路径>`。
- 写入链接前确认目标文件确实存在于仓库；push 后核验链接可访问。
- 不使用本机盘符路径、其他仓库链接或仓库外文件链接。
- 所需材料尚未纳入本交付仓库时，不编造仓库路径，也不以其他仓库链接替代；先不附该材料链接，并明确交付范围。

## 文件对应

- 周报归档：`weekly/YYYY-MM-DD.md`
- 邮件正文：`邮件/YYYY-MM-DD-周报邮件稿.txt`
